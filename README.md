# 质声智检 · Zhisheng QC

语音采集质检数据，自动判定生成标准表单，智能分析助力质量管理闭环。

面向钢板、钢卷进货检验的现场采集与管理系统。支持手机语音录入、按版本标准判定、原版式 Excel 归档、复检追溯、班组管理，以及可配置 DeepSeek 等 API 的 AI 日报和周报解读。

## 快速启动

当前运行环境为 Windows 10/11 与 Python 3.9+，推荐 Python 3.11。安卓手机通过同一网络下的浏览器访问服务，目前提供手机网页，尚未提供原生 APK。

```powershell
git clone https://github.com/Ludwigzky/zhisheng-qc.git
cd zhisheng-qc
python tools/setup_asr.py
.\run-https.bat
```

首次安装会建立项目虚拟环境、安装依赖，并下载约 227 MB 的中文离线模型。启动后先在电脑上打开窗口打印的 `https://127.0.0.1:端口` 创建部长账号，再邀请同网络内的手机用户。证书在本机首次启动时生成，手机录音需要信任该证书并允许麦克风。

仅体验手动录入、表单及管理功能时，可以跳过模型下载：

```powershell
python -m venv .venv-asr
.\.venv-asr\Scripts\python.exe -m pip install -r requirements.txt
.\run-https.bat
```

部长在“管理工作台 → API配置”设置 API Key 后，可主动生成 AI 解读。没有配置 API 时仍可查看本地规则统计解读。

公开仓库包含功能源码、安装脚本、测试、模型下载清单和去除历史签名及填写数据的 Excel 模板。账号数据库、API 密钥、私钥、录音、备份及员工实际导出文件不随源码分发；已有部署请继续使用原模板及原归档，不用公开模板替换历史记录绑定的模板。

## 功能与工作流程

管理人员登录后可从“管理工作台”进入 `#/management`。工作总览、检验台账、记录追溯、异常跟进和质量分析共用员工端的数据库。部长查看全局，室主任仅查看本班组。统计按全部符合条件的记录计算，排除示例；草稿和待核对不进入合格率分母，复检保留原首检结果。每个指标可进入明细，台账可导出筛选后的 CSV。

异常跟进支持责任人、期限、说明和带版本检查的追加历史。后续正式复检合格，或原单已正式记录拒收并确认追加失败时，可填写说明关闭跟进。原检验结论与归档文件继续按对应原记录追溯。读数目前按表单和检验轮次关联，样件、测点和量具尚无独立明细标识。

管理端回归使用独立临时数据库：`python tools/management_check.py`、`python tools/management_cases_check.py`、`python tools/management_browser_check.py`。浏览器回归从员工实际填表定稿，核对另一会话的室主任统计、追溯、异常跟进和导出，并检查桌面及手机布局。

管理工作台提供“AI解读”和“尺寸变化”。日报按所选检验日期，周报按周一至周日（本周截至北京时间今天），与上一同长度时段比较。部长可汇总或筛选班组，室主任只读本班组。解读包含首检、复检、班组汇总和当前积压待办，均可追溯原单。历史日期报告根据当前记录重算，不是历史归档快照。统计指标和正式检验结论由系统规则计算。

部长从工作台“API配置”填写基础地址、模型与 API Key，保存并测试连接后启用。默认地址 `https://api.deepseek.com`，模型 `deepseek-flash`；也支持兼容 Chat Completions 与 JSON 输出的 HTTPS 服务（基础地址根路径或 `/v1`）。AI解读页面点击“生成AI解读”才调用平台，普通刷新只读取数据或缓存；同一用户、权限、数据与配置的结果缓存24小时。提供方调用发送汇总指标、班组代号及最多60份匿名原单引用，不发送员工姓名、实际单据号、生产单位或录音。原单链接由服务器按权限重新绑定。API失败、输出不完整或引用无效时显示原因并保留本地规则解读。生成期间权限或数据发生变化时丢弃旧结果，提示重新读取。

API Key 不回显、不进入审计或源码，数据库中使用 Fernet 加密，本机加密文件为 `data/ai-secret.key`，已忽略版本控制。当前环境已有 `cryptography`；新环境需要时运行 `.venv-asr\Scripts\python.exe -m pip install cryptography`。迁移或恢复数据库后若未保留对应加密文件，需由部长重新填写 API Key。API配置包含付费平台调用，界面提供测试连接、停用和删除密钥入口。API专项回归为 `python tools/management_ai_check.py`；所有测试均使用临时数据库和模拟API响应，真实平台是否可用需在配置密钥后用“测试连接”确认。飞书暂未接入。

尺寸变化仅使用已确认钢板/钢卷首检，按班组、生产单位、牌号、规格、标准版本和实际公差分组。每份表单作为一个点，展示均值和最小/最大读数。最近 5 份覆盖至少 3 个日期、均值持续向同一边界移动至少公差带宽的 10%，且最新均值进入边界 10% 区域时提醒；窗口内有超差读数时不称为“接近”。最新表单的超差读数另行提示，数据不足时不给趋势结论。这是初始观察规则，尚未经现场数据验证，不作质量预测。回归 `python tools/management_insights_check.py` 检查权限、日周统计、空数据、跨版本公差隔离及趋势边界，浏览器回归同时覆盖新页面及手机布局。

当前主产出是员工提供的《进货检验记录》（HW/Q-JL-02A）：钢板/钢卷批次信息、资料验证、外观与尺寸口报采集，核对后按原 Excel 模板生成正式记录。该功能只覆盖进货检验环节；原来的整机多工序判定与汇总 PDF 演示继续保留。
录入、语音识别和表单生成可离线运行，无 CDN、不需要 npm install；首次语音模型安装需要联网。启用并主动生成 AI 解读时，服务端需联网调用所配置的 API。

**默认离线模型：Paraformer 中文完整版 INT8 + sherpa-onnx 2.0.1。** 安装后的运行库位于 `.venv-asr`，模型位于 `models/paraformer-zh`，默认配置在 `asr-config.json`。安装后，语音识别在本机 CPU 上离线运行。双击 `start.bat` 启动，手机录音使用 `run-https.bat`。

## 一、启动与真实账号

电脑运行 `run-https.bat`，用启动窗口打印的本机地址打开登录页。首次由操作者在这台电脑上的 `127.0.0.1` 或 `localhost` 创建部长。部长进入“账号与邀请”，为每个参与者填写账号、姓名、班组、角色，将各自的一次性邀请码交给本人。参与者在同一热点用手机访问窗口中的 HTTPS 地址，选择“使用邀请码设置密码”。以后使用自己的账号和密码登录。部长可以停用账号或发起密码重设。

部长可管理账户、检验计划及查阅历史；工艺人员发布钢板规格并审核本单临时偏差；质量工程师负责领任务、录入与确认；室主任在所属班组复核与交接。要在同一轮演示中协作，邀请时给几人填写相同的班组名。历史单保留原签名，以前的点选身份不能用于登录。

## 二、热点演示流程

1. 工艺人员从首页进入“钢板工艺标准与偏差审批”，发布有依据、带版本的规格。系统已经登记员工原表中的 5.75 × 1800 标准。
2. 质量工程师在钢板台账选择已发布版本，新建本次记录，手选资料和外观结果，录入实测尺寸。语音候选需核对。检验日期在新建时取当天的北京时间。
3. 确认后下载原版式 Excel。定稿原件随记录归档。追加复检须重新填写本轮检测结果及数量，原件仍可在台账中查看。备份、恢复与历史补档见 [钢板归档与恢复](docs/钢板归档与恢复.md)。
4. 演示整机工序时，部长从首页新建检验计划、填写负责班组和各节点的前置工序。质量工程师查看工序后主动领取，必要时交接给同组另一名质量工程师；各节点显示自己的进度。齐套后由本组室主任复核。

## 五、几个关键设计（也是这套东西能落地的地方）

**1. 表单是数据，不是代码。**
模板 = JSON（`form_templates.schema_json`），含字段、单位、上下限、公差、必填、枚举合格项、跨字段计算表达式。
工艺在「检验表单模板」页改公差 → 发布新版本 → 新任务自动用新版本，跑着的任务保持原版本并可选升级（写入留痕）。
**没有这一条，第二年标准一改就要改代码，项目就死在这。**

**2. 判定在服务端，且三版本绑定。**
每条记录落库时同时保存：`模板版本 + 标准版本 + 记录快照号（sha256 前 16 位）`。
三年后翻出这份记录，判定结果可以原样复现——这是客户审核/监理会问的第一个问题。

**3. 四态判定，不是两态。**
`合格 / 超差 / 待确认 / 缺项`。把“没测”和“测了不合格”混成一个“不合格”，质量管理上直接失效。
数值偏离基准超过 20% 判“疑似口误”转待确认，而不是直接判超差——这是口报场景的防错关键。

**4. 记录 append-only。**
复测是新记录（round+1），原记录不覆盖；页面上能翻出每一轮的判定与快照。
口报文本、识别置信度、原始音频 id 一起留档。

**5. 语音是加速器，不是唯一通道。**
口报 → 字段级填充（不是整段自由说），识别置信度低于 75% 的字段标黄，必须点“确认无误”才能提交；
键盘永远可用。ASR 引擎没装时自动走口报文本通道，不阻塞作业。

## 六、语音识别（本地、零下载、无硬件）

### 6.1 链路

```
手机浏览器（16k 单声道 WAV 直采，可选系统降噪）
   → /api/asr/audio  留档原声
   → 音频指标：时长 / RMS / 噪声底 / SNR / 语音占比 / 削波率
   → （可选）服务端谱减降噪支路
   → 识别引擎（可选本地 Paraformer / SAPI zh-CN / faster-whisper；无引擎明确提示）
   → 原声为主、可选降噪对照；读数冲突必须确认
   → 文本 + 实际识别评分 → 中文数字/单位归一 → 字段落格
   → 判定 / 标黄确认 / 键盘兜底
```

### 6.2 引擎

| 引擎 | 条件 | 说明 |
|---|---|---|
| **sapi** | 已安装、当前进程可用的 Windows zh-CN 识别器 | 全离线；`asr_engine.py` 优先尝试 32 位 PowerShell，再尝试 64 位宿主，实际可用性以自检为准 |
| sherpa-onnx | 安装运行库 + 本地离线 Paraformer ONNX 和 tokens | 可复用同一模型到安卓；本适配器不支持 SRGS/热词，不伪造置信度，结果须人工确认；见第十一节 |
| faster-whisper | `pip install faster-whisper` + 放好模型 | 装了才启用，接口一致 |
| stub | 兜底 | 只留档 + 算指标，文本走键盘/示例 |

启动时服务端会把引擎拉起来并打印状态：

```
[init] asr engine: sapi ready
[init] asr engine: stub unavailable -> LoadGrammar: Access is denied
```

### 6.3 采集设置（没有耳麦时能调的就这三样）

任务页底部「降噪 / 原声」入口：

- **系统降噪**（默认）：`noiseSuppression / echoCancellation / autoGainControl = true`
- **原声**：三项全关，用于做对照实验
- **服务端降噪支路**：谱减（增益下限 0.10，时间平滑 3 帧），可选开

界面会显示**浏览器实际生效的参数**（`track.getSettings()`），不是我们请求的参数——这两者经常不一样。

### 6.4 识别实验室（出数据的地方）

首页 →「识别实验室」，10 句固定脚本，覆盖整数、小数、单位、枚举、超差、口误：

| 指标 | 含义 |
|---|---|
| 字段命中率 | 识别文本经解析后，目标字段值与期望一致（按字段精度取容差，整数字段差 1 就判错） |
| 字符错误率 CER | 先做中文数字归一（「二万二千五百」→ 22500）再算编辑距离，否则数字会被算爆 |
| SNR / 噪声底 / 削波 | 判断「听不清」是环境问题还是交互问题 |
| 分组对比 | 按 `系统降噪 / 原声` × `是否服务端降噪` 自动分组统计 |

10 句录完可得到一张对照表；识别耗时和真实准确率取决于引擎、手机、口音和环境，不能由功能自检推算。

### 6.6 语法约束识别（SAPI 可选能力）

**语法约束**把搜索空间限制在「当前字段或表单的标签 + 数字 + 单位 + 枚举项」。这能减少部分术语错误，但不改变声学模型，也可能拒识词表外的说法，实际收益须用同一批录音测量：

| 模式 | 搜索范围 | 结果 |
|---|---|---|
| 自由听写 dictation | 通用中文词典 | 开放式，噪声/口音一错就整句飞 |
| **语法约束 grammar** | 当前字段的别名、数字、可换算单位、枚举及否定词；未指定字段时使用全表 | 限制候选范围，仍须核对数值与否定词 |

实现：`backend/asr_grammar.py` 把模板编成 SRGS（`.grxml`），服务端在每次识别前 `LOAD` 给引擎；
加载失败会自动回落听写，并在页面上显示失败原因（不会静默变差）。

页面上两处入口：

- 任务页底部「降噪/原声」→ 采集设置 → **识别模式：语法约束 / 自由听写**
- 识别实验室顶部会显示当前模式与「已加载语法（N 条）/ 加载失败原因」

**配套的口报协议（很重要）**：语法模式下达标说法是「一项一句、一位一位报」：

```
跨度 二 二 五 零 一
主梁上拱度 二 六 点 五
焊缝外观 合格
```

逐位报比整句自然说更容易被识别命中——这不是妥协，是工业现场的通行做法（报数、复诵、核对）。

### 6.7 在你本机出真实数据（沙箱里做不到）

环境受限时 SAPI 可能返回 `E_ACCESSDENIED`，先自检再启动。功能自检与合成音不能代替真实手机录音的准确率评测。两步：

```bat
check-asr.bat          :: ① 先自检：3 秒告诉你本机能不能跑本地识别
run-https.bat          :: ② 再启动服务（手机录音必须 HTTPS）
```

`check-asr.bat` 现在检查实际选中的识别引擎，使用项目内 Python，不再只检查 Windows SAPI。输出包括 `available`、实际模型、运行库版本；当前应看到：

```
"engine": "sherpa-onnx"
"available": true
"model": "model.int8.onnx"
"runtime_version": "2.0.1"
```

1. 打开 <https://本机IP:8760>，用**手机**访问（手机麦才是现场真实拾音）

**判读方式**（对应之前的可行性结论）：

> 页面上「引擎不可用」里如果写着 `Access is denied`，意思是**这个服务进程**没有语音权限；
> 点「重新检测」会重试一次，但真正解决要用 `check-asr.bat` 确认后，在你自己的终端重启服务。

## 十一、2026-11-10 语音准确性修复与安卓路线

### 已落地的改进

| 问题 | 现在的行为 |
|---|---|
| 识别返回新文本，却读页面旧输入框解析 | 显式解析本次转写；录音开始时固定任务、字段和采集配置，避免等待上传时切字段造成错填 |
| “不合格”命中“合格”，“不可靠”命中“可靠” | 否定与不确定语义优先；泛称“不合格”保留原意、要求确认，不猜具体缺陷 |
| “二 二 五 零 一”被取成单个 2 | 支持逐位中文/混合数字、空格、小数点、负号、全角输入 |
| 从多个读数中擅自挑最长数字 | 两个独立读数不猜值；未输出标点时按明确字段标签分段 |
| 单位截断、复合单位混淆 | 长单位优先，支持毫米每米、兆欧/欧姆等；不兼容单位降评分待核对 |
| 按表单精度四舍五入掩盖超差 | 保留真实读数参与判定，例如 2.54 不会先变成 2.5 |
| 解析器覆盖真实 ASR 低分；零分反而免确认 | 字段评分取解析与声学评分较低者；零分/不可用也进入待确认，新读数清除旧确认 |
| 原声和降噪读数冲突却自动择高分 | 比较字段和值；冲突强制标黄，保留两支路文本供核对 |
| 默认谱减、默认模拟可能掩盖失败 | 新会话默认关闭服务端谱减和模拟；原声先测，再决定是否开降噪。已保存的用户设置继续生效 |
| SAPI 默认语言不确定、长停顿丢后半句 | 显式选择 zh-CN，循环读取有限 WAV；模式配置和识别在同一锁内，防并发串语法 |
| 降噪丢失窗口末尾样本 | STFT 补齐两端并裁回原长度，避免最后读数尾音被置零 |
| 实验室把接近答案的错误读数计为正确 | 字段命中要求数值等价；例如 22501.4 不算 22501 命中 |

识别评分不是正确率，也没有经过现场概率校准。代码没有按公差把读数“修成合格值”。

### 安卓可复用的引擎

SAPI/SRGS 只用于 Windows。新增 `backend/asr_sherpa.py`，采用本地离线 Paraformer 的 `model.int8.onnx`（或 `model.onnx`）及 `tokens.txt`。官方 [Android 实现](https://k2-fsa.github.io/sherpa/onnx/android/index.html) 和 [Kotlin API](https://github.com/k2-fsa/sherpa-onnx/blob/master/sherpa-onnx/kotlin-api/OfflineRecognizer.kt) 可复用这一模型结构。

当前优先落地官方 [Paraformer 中文完整版](https://huggingface.co/csukuangfj/sherpa-onnx-paraformer-zh-2024-03-09)，INT8 文件为 227,330,205 字节。后续可用约 79 MB 的 small 模型对比安卓体积和耗时，但本次尚未安装 small，也没有声称完整版已在现场准确率上胜出。

以下为 **PowerShell** 命令，在 `qc-demo` 下执行；当前电脑已经完成安装，新电脑或需要修复安装时使用：

```powershell
python tools/setup_asr.py
.\run-https.bat
```

安装器固定运行库版本与模型仓库提交，校验模型 SHA-256 和词表 Git 内容哈希，真实初始化成功后才写入默认配置。`.venv-asr` 复用已有 Flask/NumPy/SciPy；缺少依赖时仅在项目环境中补装，不修改全局 Python。识别请求不触发下载。`ASR_ENGINE`、`ASR_SHERPA_MODEL_DIR` 可显式覆盖本地配置。

启动时显示实际引擎和模型缺失/加载失败原因。显式选择失败不会静默换引擎；`ASR_ENGINE` 可设 `auto`、`sapi`、`sherpa-onnx`、`faster-whisper`、`stub`，改后重启服务。`auto` 优先尝试已配置的 Paraformer，其次 SAPI 和本地 Whisper，最后 stub。Whisper 缺少本地模型时也不会偷偷联网下载。

当前 Paraformer 适配器没有可靠的整句置信度，所有填入值要求人工确认；它不支持本项目的 SRGS，也没有接入热词偏置。Whisper 则按当前字段生成术语提示，使用实际解码分数而非固定 0.9；分数仍未经概率校准。

安卓迁移建议分两步：

1. 保留当前后端业务闭环，先在安卓浏览器通过 HTTPS 验证真实手机麦克风和口音，不把笔记本合成音当现场数据。
2. 需要手机独立离线运行时，用原生 [AudioRecord](https://developer.android.com/reference/android/media/AudioRecord) 采集单声道 PCM，转换为 16 kHz，接 sherpa-onnx Kotlin/JNI；移植数字/单位/否定词解析、人工确认与留档协议，并复用回归语料。Python/Flask、PowerShell 和浏览器录音代码不能直接变成安卓原生组件。当前未生成 APK，也未验证真机内存、发热和延迟。

正式表单的总判定包含资料、外观、每次尺寸读数、补充尺寸及批量数量。只要有一项不合格，左侧结论格填写“不合格”。确认不合格记录后，自动建立一份关联的同批次草稿，但页面停留在已生成的原记录，先供员工核对预览和下载；点“继续填写后续表单”才进入下一份。后续草稿沿用材料与标准，清空所有检测结果、数量、处理结论和语音候选，要求员工重新填写。上一份不合格记录仍可查看、下载，重复点击追加复检会返回同一份后续表单。

正式导出前，资料、外观、尺寸、批量数量与日期必须填写完整，所有口报字段必须人工核对确认。正式记录绑定模板哈希、质量工程师与快照，锁定后不能覆盖，只能追加复检。确认姓名取当前登录账号；来表内的原员工签名图片不会复制到新记录，也不会作为未使用的图片残留在导出文件中。演示账号确认不等同于CA数字签章。

现有 **23个语音字段**：7项批次材料、2项厚宽读数、6项公称值和偏差、8项补充尺寸。**第2节“资料验证”、第3节“外观检查”的7项只允许手选，第5节“批量检验结论”的7项仅手动填写**，不提供语音入口或接受对应语音请求。历史资料/外观语音候选只保留原话与舍弃入口，须到对应检验项手选结果。点字段旁麦克风开始，说完点底部停止。单据号逐位报数保留前导零，日期需报完整年月日，负偏差可说“负零点二九”。质量工程师姓名由登录身份确定。

输入稍停即自动保存草稿及待核对语音；手机当前标签页还会暂存尚未写入服务器的修改，刷新时只在草稿版本匹配时恢复。点“预览当前草稿”或“生成检验记录 Excel”会补收手机自动填充和最后一次输入，保存后再读取本单的预览或定稿。待核对的语音不会自动成为正式检测值。正文“保存与生成 Excel”始终可找到：未通过核对时显示具体问题，点击问题回到相应项目；通过后显示带单据号的正式下载卡。旧草稿如只留下识别日志，可在“查看历史识别原话”中手工参考，原话不代表已确认的检测结果。

识别结果会在对应表单格预填并标记“语音预填，待核对”，同时进入核对区，可修改、确认、重录或舍弃。确认前正式数据保持已保存值，待确认时服务端禁止生成正式记录；候选保存草稿后刷新仍保留。手动修改对应格会替代旧候选。原始转写与录音保持留档，切换记录或修改内容后的旧转写不串填。

底部录入面板默认收起为小栏。点击录音时先同步显示“正在打开麦克风”的小型提示和取消按钮，再调用浏览器录音接口。录音时工具保持收起，当前字段麦克风变为红色停止状态，再点即结束并识别；底部小栏也可停止。点小栏可手动展开，手动滚动表单可收起。启动失败会保持错误提示展开，取消或识别完成后收起。录音阶段仅更新状态，避免整个表单重建造成焦点和滚动错位。资源URL带版本号，防止手机混用旧脚本与样式。

当前字段的红色录音按钮滚出可视区域时，屏幕上方显示一行小型停止提示，不遮挡大块表单；停止后上传和识别期间，所有录音按钮立即禁用并变灰，完成或失败后恢复。若旧端口被占用，启动窗口会换到新端口，手机须使用该窗口显示的完整HTTPS地址。

底部输入框的文字在停顿约0.8秒、点击键盘完成、回车或移出输入框后自动同步至选中字段，无需再点同步；中文输入法组词期间不会提前提交。文字按相应字段解析单号、日期、数字及结论，作为手动确认输入；未识别的内容保持提示，不能猜值。切换字段及旧请求返回时不会串填。

数值口报“一千一”到“九千九”的81种省略百位说法按1100到9900解析，也支持“1千1”等中阿混写；明确的“一千零一”仍为1001，“一千一十”仍为1010，单据号和日期不使用这条口语规则。规格中的数字“乘／乘以／乘上”归一为星号，例如“五点七五乘一千八”→`5.75*1800`；非数字操作数不会被拼成规格。规则作用于识别出的文字，保留原话供人工核对，不会把已经识别成`1001`的纯数字猜改成1100。

“合格／不合格”使用独立判定词表，完整近音“何格／和格”“不何格／不和格／布合格”可生成注明原话的待核候选。“不，合格”、否定、疑问、不确定及冲突语句均拒绝自动判定，厂家等自由文本不做替换。当前Paraformer不支持解码热词偏置，词表作用在判定候选归一阶段，原始转写、置信度及人工确认要求均保留；尚未据此宣称真机准确率提升。

页面已为安卓手机浏览器适配：窄屏单列、至少44px触控按钮、16px以上输入、材料/资料/外观/尺寸/结论快捷跳转，底部固定口报与保存/生成操作，预留安全区、键盘和操作栏空间，允许双指缩放。手机通过HTTPS访问现有后端；这一步是移动Web界面适配，尚未打包安卓APK，仍需在目标安卓手机验证软键盘、麦克风权限及现场录音表现。

手机录音启动会在点击时直接申请麦克风并恢复音频，不需先等待草稿保存或页面渲染。等待权限最多12秒，获得权限后等待音频恢复最多5秒；可随时点“取消”，失败后会恢复按钮并保留具体原因与“重试录音”。取消或超时后迟到的媒体流会立即停止。识别完成后候选随草稿自动保存，须经人工核对才能进入正式记录。浏览器网站设置和安卓应用设置都需要允许麦克风；HTTPS证书告警的排查方法见录音问题栏。

某些手机自带浏览器不会返回网站麦克风权限，可点底部 **“系统录音 / 导入”**：支持的浏览器会打开系统录音；如果出现文件选择界面，先在手机录音机里录制并保存，再选择该音频。它不使用网页麦克风权限。浏览器会将能解码的音频转为16kHz单声道PCM WAV，再发送给相同的本机识别接口，结果仍需核对确认。每段0.3～30秒、文件不超过10MB；M4A/MP3/WAV等格式能否解码取决于手机浏览器，格式不支持会明确提示，不会将压缩文件冒充WAV上传。选择文件前固定当前检验项，取消选择不锁页面。

失败提示中可展开权限设置帮助，下载 `qc-demo-ca.cer` 公共测试证书，按手机系统要求手动确认安装CA证书；仅信任自己控制的电脑生成的证书。下载文件不包含私钥。新的 `/api/asr/certificate`、`/api/asr/microphone-help` 及登录后的同源 `/api/asr/microphone-report` 提供证书、帮助与本机诊断留档；“保存本机诊断”仅记录浏览器、权限、安全连接及错误状态，不保存表单或音频。新增后端接口需重启Demo，静态界面及导入录音入口刷新即更新。

表格库的通用导入/导出会丢失原表的Office Math对象，已通过对比验证。因此应用使用原始XLSX包定点填值，保留原生宽度公式，并同步更新其普通文本兼容表示。报表服务只依赖Python标准库，不依赖安装Excel、Node或联网；真实Excel只用于本次版式与打印核对。

`steel_records` 为新增独立数据表，创建不会清除已有任务、录音或记录。钢板记录存在后，旧演示重置入口会拦截，以保护口报留档。常用接口为 `/api/steel/template`、`/api/steel/records`、`/api/steel/asr/audio`、`/api/steel/asr/parse`；保存、确认、追加复检、预览和XLSX下载均按记录ID操作。

## 十三、通过 UUMIT 在手机公网访问

程序与识别模型仍运行在这台电脑。`run-uumit.bat` 以HTTP启动本机127.0.0.1:8870（被占用时自动换空闲端口），由UUMIT提供手机访问的公网HTTPS入口。启动器每次生成随机会话密钥，Cookie名称独立，不向其他应用复用。电脑、Demo与UUMIT客户端都需保持运行。

在已连接本人账号的UUMIT客户端中，将启动窗口显示的端口发布为“只有我”。命令行示例（端口按实际启动结果替换）：

```powershell
& "$env:LOCALAPPDATA\Programs\UUMit\uumit-connector.exe" publish 8870 --to private --name weihua-iqc --title "卫华钢板检验" --json
```

首次连接电脑需要本人在UUMIT确认设备。使用企业账号模式时仍应限制网关访问范围。前端已兼容UUMIT的`/s/服务名/`路径，API、WAV上传、预览及Excel下载跟随相同前缀。手机请直接打开发布结果的完整HTTPS应用地址，登录同一UUMIT账号后使用。公网HTTPS可解决局域网自签证书的信任问题，但浏览器和安卓仍需允许麦克风权限。
